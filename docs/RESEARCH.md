# Research and implementation decisions · 21 November 2026

## Runtime and distribution

- **CEP HTML + ExtendScript** is the initial production-host target. AEFT is the host identifier; Adobe documents CEP 12 for AE 25+. Bound the initial manifest to AE 25–27. Dispatch fixed registered commands from a local HTML UI. No panel-side Node, servers, polling, remote code or network requirement for normal operation. Test 26.x and 27.x on Windows; a manifest range is not certification. [Adobe CEP 12 cookbook](https://github.com/Adobe-CEP/CEP-Resources/blob/master/CEP_12.x/Documentation/CEP%2012%20HTML%20Extension%20Cookbook.md)
- **UXP** entered public beta in AE 27.1.0.045 (UXP 9.4) on November 17. Adobe targets GA in Q2 2027. Do not make beta installation a prerequisite. Probe stable selection/text/marker/undo/file access before migrating. [Beta announcement](https://community.adobe.com/announcements-532/after-effects-is-adding-uxp-plugin-support-public-beta-now-open-1656525) · [Adobe migration milestones](https://developer.adobe.com/uxp/migration-center/)
- **ExtendScript** owns synchronous project edits. Use documented match names, bulk validation and one closed Undo scope. Expressions evaluate values per sample without mutating the project. ScriptUI is suitable for small utilities but constrains styling. Native C++ effects are appropriate for pixel algorithms; this product initially orchestrates existing DOM operations. [AE developer hub](https://developer.adobe.com/after-effects/) · [AE scripting guide](https://ae-scripting.docsforadobe.dev/) · [AE SDK](https://ae-plugins.docsforadobe.dev/)
- **Packaging**: use the signed CEP package format, identity-stable manifest and current-user installation. No global CEP debug switch. Signing keys are independent from panel settings and excluded from source. [Adobe package guide](https://github.com/Adobe-CEP/Getting-Started-guides/tree/master/Package%20Distribute%20Install) · [Adobe signing compatibility note](https://github.com/Adobe-CEP/CEP-Resources/blob/master/ZXPSignCMD/KnownIssue2024.md)

| Duplicate / cleanup | Traverse source-use graph with a visited map; handle shared subcomps once per duplication policy. | Folders / templates | Local folder nodes in a project, typed paths for future templates, idempotent exact-name matching. | Duplicate sibling folders, colliding non-folder items, nested roots, user renames; do not reorganize disk files. [ItemCollection](https://ae-scripting.docsforadobe.dev/item/itemcollection/) |
| Sort / rename / search | Classify Project selection by host type then media interpretation/extension. Plan original IDs, destinations and generated names before applying. | Effects / animators / layer sets | FFX for approved property stacks, AEP template comp for interdependent layers, explicit modules for procedural rigs. Native UI saves FFX. Compose predictable steps under one host command. | Duplicate names, prior partial installation, deleted controls, localized properties and mutually dependent targets. Never recursively invoke separate undo scopes. |

## Marker timing and preset intake

V1's example is a character reveal: an opacity-zero text animator selects the suffix after its percentage Start. Start moves from 0 to 100 by **AE Tools · IN END**. At that marker all text has appeared. Optional **OUT START** and **OUT END** drive the reverse transition to zero. Source Text and its style runs remain untouched; other animator groups continue to contribute. Markers live on the layer in comp time. Defaults come from frame counts × actual comp frameDuration. Markers follow user edits immediately. Sample at exact time and subframes; do not round expression time. The final default exit marker is on the last visible frame.

For a supplied asset, record its original FPS, sample interval, ease/overshoot, animator order, selectors, effects, fonts, expression engine and external controls. Apply FFX once to an isolated sample layer; open AEP in a separate project. Never modify the supplied original. Compare reference and rebuilt frames at 0%, 25%, 50%, 75%, 100% plus overshoot extremes. Map normalized marker progress to the **authored time range**, sampling independent keyed driver properties at original time to preserve interpolation. Do not replace every property with linear interpolation, resample Source Text, or stack another timing expression on an existing dependent expression. For reference-dependent presets use an explicit adapter; for nonseparable stacks document the limitation or keep an isolated template comp. A whole-layer time remap changes other animation and is inappropriate for an existing styled text layer.

Reject duplicate/reserved endpoint collisions on installation. For a moved/deleted marker use the rig's documented clamped fallback; test crossing markers, subframe edits, negative input, very short layers, trimming, display-start offset, 23.976/25/29.97/60 and mixed-style multilingual text. Layer-local IN progression always starts from the live inPoint. Record exact expression property, output type and engine. A new preset must include a reference asset the owner can redistribute or a reproducible synthetic fixture.
