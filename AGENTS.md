# Extending AE Tools

Start with PROJECT_STATE.md and docs/ROADMAP.md. Keep the bundle and preference IDs stable. The product owns only this repository and its own installed extension directory.

1. Define one stable ID, title, category, Lucide asset, description and typed parameters in panel/catalog.json. Reuse an existing category where appropriate. New category labels appear automatically. Store a licensed icon under panel/icons. Never expose a tile without its handler.
2. Add register(id, function(args){...}) in a file under host/modules. The build collects these modules into one private ES3 closure. Validate the entire input and selection; return zero or more synchronous mutation closures. Zero steps means no change. Re-resolve indexed children after structural edits. Leave outer Undo ownership to the dispatcher. Do not add arbitrary eval or send user-entered strings as JSX.
3. Most commands need no UI changes. Choices, frame counts, saved defaults, favorites, hiding, full-width tiles, reordering and diagnostics come from shared components. An inline widget belongs only to a genuinely spatial or temporal control. Use registered integer arguments; extend the wire protocol explicitly before introducing other types.
4. For FFX, AEP, expressions and rigs follow docs/RESEARCH.md (Marker timing and preset intake). Preserve source assets, record permission to redistribute and avoid public commits containing private production examples. Define owned channels, unsupported states, idempotence and a change/undo recipe. Add a licensed or synthetic reference case.
5. Run npm ci, npm test, npm run test:ui. Use a clean build for packaging. Review PROJECT_STATE.md for the remaining real-host matrix. Publish a new immutable version for different release bytes; never overwrite issued downloads. A normal production release uses an owner-controlled signing certificate, not the one-off foundation preview signer.
